# Microsoft 365

`annals-m365` (`cmd/annals-m365`, `internal/m365`, in Annals' image)
reads the Microsoft 365 unified audit log and posts one event per action as
the source its Annals token allows (`m365`). Every pass starts an audit log
query on Microsoft Graph (`POST /security/auditLog/queries`) for the record
types `sharePointSharingOperation` and `copilotInteraction`, waits for it,
and posts what it finds in batches. Nearly every record reaches the audit
log within two hours, and a few up to a day late. So each pass reads back 3
hours (`RECENT`), and once a day, and on the first pass after a start, a
pass sweeps 48 hours (`LOOKBACK`). The `event_key`, the audit record's id,
makes the repeats free.

It signs in to Graph as its own app registration with the pod's federated
workload token, never a secret, and needs the application permission
`AuditLogsQuery.Read.All` with admin consent.

| Setting | Default | Meaning |
|---|---|---|
| `ANNALS_URL`, `ANNALS_TOKEN` | required | Annals' API port and a token issued for `ANNALS_SOURCE`. |
| `ANNALS_SOURCE` | `m365` | The source the token posts as. |
| `AZURE_TENANT_ID`, `AZURE_CLIENT_ID`, `AZURE_FEDERATED_TOKEN_FILE` | required | Set by the workload identity webhook. |
| `INTERVAL`, `LAG` | `30m`, `15m` | How often a pass runs, and how much of the newest window it leaves for the log to fill. |
| `RECENT`, `LOOKBACK`, `SWEEP` | `3h`, `48h`, `24h` | How far back a pass reads, how far back a sweep reads, and how often a pass sweeps. `RECENT` of `0` makes every pass a sweep. |
| `GRAPH_URL` | `https://graph.microsoft.com/v1.0` | |

Metrics: `annals_m365.records` by record type and whether it mapped,
`annals_m365.events` by receipt status, `annals_m365.passes` and
`annals_m365.pass.duration` by outcome and kind (`sweep` or `recent`). Logs: `pass done` with its kind and counts,
`pass failed` with the error, and `event not stored` for each refusal.

## Sharing

Every sharing record is one event. The operations that grant access
(`SharingInvitationCreated`, `SharingSet`, `AddedToSecureLink`,
`AddedToSharingLink`, `AnonymousLinkCreated`, `CompanyLinkCreated`,
`SecureLinkCreated`, `SharingLinkCreated`) become `<kind>.share`; the rest of
the record type (a link used, inheritance broken, access revoked) become
`<kind>.sharing.<operation>`. The kind is `site`, `file`, `folder`, or
`list` from `ItemType`.

| Record | From the audit record |
|---|---|
| `actor` | `kind: person`, `id` the record's `userId`, `email` its `userPrincipalName`; when `userId` is a SharePoint claims login (`i:0h.f\|membership\|...`), `id` is the `userPrincipalName`; a service or application account, and SharePoint's own `app@sharepoint` under any login, is `kind: system` |
| `action.target` | `system: sharepoint` or `onedrive`, `id` the `ListItemUniqueId` or `ObjectId`, `title` the file name, or the site URL for a site |
| `parties` | one `recipient`: a person by full email from `TargetUserOrGroupName`, `external` when `TargetUserOrGroupType` is `Guest`; a group by name; `anyone` for an anonymous link; the organization for a company link |
| `change.summary` | the access given, such as `edit access`, from `EventData` |

See `schema/examples/sharepoint-share.json`. The recipient's email is kept,
not only its domain, and only a PII reader or an admin sees it.

## Copilot

A `CopilotInteraction` record becomes one `prompt.send` record for the
person, with `event_key` `copilot:<record id>`, and one `tool.call` record
per plugin or agent the prompt set off, keyed `copilot:<record id>:tool-<n>`
with `cause` set to the prompt's key:

| Record | From the audit record |
|---|---|
| prompt `actor` | the person who sent the prompt |
| prompt `agent` | `runtime: copilot`, `harness` `m365-<AppHost>`, `session_id` the `ThreadId` |
| prompt `action.target` | `system: m365-copilot`, `kind: thread`, `id` the `ThreadId`, `title` the app |
| prompt `items` | every `AccessedResources` entry: its id, name, type, action (`read` when none), and `SensitivityLabelId` |
| tool `actor` | `kind: agent`, `id` `m365-<AppHost>`, `on_behalf_of` the person |
| tool `action.target` | `system: m365-copilot`, `kind: tool`, `id` the `AISystemPlugin` id, `title` its name |

See `schema/examples/copilot-prompt.json` and `copilot-tool.json`. The audit
log does not hold the prompt's text, and the record never does either.
Free text that holds an email address, such as a file named for a person,
has the address replaced with `[email]`.
